# TripNest AI: API Documentation

Base URL: the same origin as the web app (local: `http://localhost:8000`). Interactive documentation generated by FastAPI: **`/docs`** (Swagger UI) and **`/openapi.json`**. All endpoints are `GET`, need no authentication or API key, and return JSON. Errors use `{ "detail": "message" }` with HTTP 404 (not found) or 422 (invalid input).

Only the two core features and their supporting data are exposed. Itinerary, community, review, weather, account and admin endpoints are **not mounted** (the code is kept, unmounted).

## Core feature 2: recommendation

### `GET /api/recommendations?lat=13.0827&lon=80.2707&date=2026-12-26&interest=beach&limit=2`

## Locations

`GET /api/locations/search?q=chen` returns up to 8 matching cities. `GET /api/locations/resolve?q=Bangalore` resolves typed text (aliases and ", State" suffixes are understood):

```json
{"name": "Bengaluru", "state": "Karnataka", "lat": 12.9716, "lon": 77.5946}
```

Unknown text returns 404 with a message asking for a nearby major city. `GET /api/locations/all` lists all 77 cities.

## Explore (the location-first screen)

### `GET /api/explore?lat=11.0168&lon=76.9558&date=2026-12-26&interest=wildlife&slot=all`
`lat`, `lon` and `date` are required; `interest` is optional (letters only, 30 characters); `slot` is `all`, `early`, `morning`, `afternoon` or `evening`. Returns `origin` (the nearest listed city, its `distance_km`, `covered` and a `label` for the greeting), `popular` (catalogue popularity at least 0.9, nearest first; `popular_expanded` and `popular_note` say if the radius had to widen), `hidden_gems` (popularity at most 0.8, predicted Low or Moderate; each with `reasons`, `classification_reason`, `score`, `breakdown` and, where one exists, `alternative_to`), `map` points (`group`, `level`, `color`, `blurb`, `image_url`, `best_label`), `classification` thresholds, `method` and `provenance`. Each card carries `image` (URL, credit, licence), straight-line `distance_km`, `crowd`, `best_window` and `timeline`; `best_window` is null when the data cannot support a recommendation. Invalid coordinates or dates return 422.

### `GET /api/locations/nearest?lat=..&lon=..`
Names the closest listed city for a browser position, used for the greeting ("around X", or "near X" when it is far). The response echoes the position rounded to 2 decimals (`query_lat`, `query_lon`) and its `distance_km` from the city.

## Supporting endpoints

- `GET /api/destinations?q=&state=&category=&budget=&month=&page=&limit=` lists destinations. `GET /api/destinations/{slug}` gives one with its attractions.
- `GET /api/crowd/compare?slugs=goa,jaipur&date=2026-12-26` compares up to 5 destinations hour by hour.
- `GET /api/crowd/map?at=2026-12-26T12:00` gives every attraction's predicted level and a map `heat` value (0 for Low and Closed, so quiet places stay uncoloured).
- `GET /api/destinations/{slug}/photo` and `GET /api/attractions/{slug}/photo` return a Wikimedia Commons photo with credit and licence, or `available: false` with a reason.
- `GET /api/model` returns the model card (split dates, row counts, metrics, baselines). `GET /api/health` returns service, database and model status.

## Conventions

- No API key or login is needed. Browser state-changing requests are not used (all endpoints are read-only).
- Every prediction response carries `provenance`: `type: model-predicted`, `training_data: demonstration`, `generated_at`, `model_trained_at`.
- Responses never contain private data; no personal data is stored.
